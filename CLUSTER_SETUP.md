# Compute Canada Cluster Setup Guide

This document describes how we got the FlappyBird LGP evolution project working on the Digital Research Alliance (Compute Canada) cluster.

## The Problems

1. **`flappy-bird-env`** is not available in the cluster's wheelhouse
2. **`opencv-python`** has a dummy package that requires special handling
3. **Package versions** must be flexible to match cluster-specific builds
4. **Conda paths** in requirements.txt don't exist on the cluster

## The Solutions

### 1. Copy `flappy_bird_env` Directly Into the Repo

Instead of installing via pip, we copied the entire `flappy_bird_env` package into the project:

```
LGP_Vision/
├── flappy_bird_env/       ← Copied from flappy-bird-env repo
│   ├── __init__.py
│   ├── flappy_bird_env.py
│   ├── bird.py
│   ├── pipe.py
│   ├── images/
│   └── ...
├── run_flappy_bird.py
└── ...
```

**Why this works:** Python first looks in the current directory for imports. When you `import flappy_bird_env`, it finds the local `flappy_bird_env/` directory.

### 2. Clean `requirements.txt` with Flexible Versions

The original `requirements.txt` had conda-specific paths like:
```
appnope @ file:///home/conda/feedstock_root/...
```

These don't exist on the cluster. We replaced it with a clean version using `>=` for flexibility:

```txt
# Essential packages for FlappyBird LGP Evolution
numpy>=1.25.0
scipy>=1.14.0
gymnasium>=0.29.0
pygame>=2.5.0
matplotlib>=3.8.0
PyYAML>=6.0
torch>=2.2.0
torchvision>=0.17.0
cloudpickle>=3.0.0

# opencv-python - DO NOT include here, loaded via module
```

**Key points:**
- Use `>=` instead of `==` to allow cluster-specific versions (e.g., `pygame==2.5.2+computecanada`)
- **DO NOT** include `opencv-python` in requirements (use module instead)
- Remove `flappy-bird-env` (it's in the repo)

### 3. OpenCV Setup (CRITICAL)

OpenCV on Compute Canada requires special handling. The cluster has a **dummy** `opencv-python` package that will fail if you try to pip install it.

#### The Correct Solution

Per the [Alliance OpenCV documentation](https://docs.alliancecan.ca/wiki/OpenCV):

1. **Load `gcc` and `opencv` modules with specific versions BEFORE creating virtualenv:**
   ```bash
   module load gcc/12.3
   module load python/3.10
   module load opencv/4.8.1
   ```

2. **Create virtualenv with `--system-site-packages`:**
   ```bash
   virtualenv --no-download --system-site-packages $SLURM_TMPDIR/env
   ```

3. **Exclude opencv from pip install:**
   ```bash
   grep -v "opencv" requirements.txt > $SLURM_TMPDIR/requirements_wheelhouse.txt
   pip install --no-index -r $SLURM_TMPDIR/requirements_wheelhouse.txt
   ```

#### Why This Works

- `module load opencv/4.8.1` provides the actual OpenCV C++ library and Python bindings
- `--system-site-packages` allows the virtualenv to see the module-provided `cv2`
- The `gcc` module is required as a dependency for opencv
- Excluding opencv from pip install prevents the dummy package error

#### Common OpenCV Errors and Solutions

| Error | Solution |
|-------|----------|
| `ModuleNotFoundError: No module named 'cv2'` | Add `module load gcc/12.3` and `module load opencv/4.8.1` |
| `This is a normal error generated by this dummy wheel` | Don't pip install opencv-python, use module instead |
| `opencv module must be loaded before activating virtualenv` | Load modules BEFORE `source .../activate` |

## Complete SLURM Script

```bash
#!/bin/bash
#SBATCH --account=def-skelly
#SBATCH --job-name=flappy_evolution
#SBATCH --nodes=1
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=32
#SBATCH --mem-per-cpu=128M
#SBATCH --time=08:00:00
#SBATCH --output=evolution_%j.out
#SBATCH --error=evolution_%j.err
#SBATCH --mail-user=your_email@mcmaster.ca
#SBATCH --mail-type=ALL

# Change to submission directory
cd "$SLURM_SUBMIT_DIR" || exit 1

seed=${1:-42}

# Load required modules BEFORE creating virtualenv
# See: https://docs.alliancecan.ca/wiki/OpenCV
module load gcc/12.3
module load python/3.10
module load opencv/4.8.1

# Create virtual environment with system site-packages (for opencv access)
virtualenv --no-download --system-site-packages $SLURM_TMPDIR/env
source $SLURM_TMPDIR/env/bin/activate

# Upgrade pip
pip install --no-index --upgrade pip

# Install packages (excluding opencv since it's provided by module)
grep -v "flappy-bird-env\|opencv" requirements.txt > $SLURM_TMPDIR/requirements_wheelhouse.txt
pip install --no-index -r $SLURM_TMPDIR/requirements_wheelhouse.txt

# Verify cv2 is available from module
python -c "import cv2; print(f'✓ cv2 version: {cv2.__version__}')" || {
    echo "ERROR: cv2 not available!"
    exit 1
}

# Verify flappy_bird_env package exists
if [ ! -d "flappy_bird_env" ]; then
    echo "ERROR: flappy_bird_env package not found!"
    exit 1
fi

# Verify import works
python -c "import flappy_bird_env; print('✓ flappy_bird_env imported successfully')" || {
    echo "ERROR: flappy_bird_env import failed!"
    exit 1
}

# Set random seed
export PYTHONHASHSEED=$seed

# Print job info
echo "=========================================="
echo "Job ID: $SLURM_JOB_ID"
echo "Node: $SLURM_NODELIST"
echo "CPUs: $SLURM_CPUS_PER_TASK"
echo "Working directory: $(pwd)"
echo "Random seed: $seed"
echo "=========================================="

# Run evolution
python run_flappy_bird.py config.yaml

echo "=========================================="
echo "Job completed at $(date)"
echo "=========================================="
```

## Troubleshooting

### Error: `ModuleNotFoundError: No module named 'cv2'`
**Solution:** 
1. Add `module load gcc/12.3` and `module load opencv/4.8.1` BEFORE virtualenv creation
2. Use `--system-site-packages` when creating virtualenv

### Error: `This is a normal error generated by this dummy wheel`
**Solution:** Don't include `opencv-python` in requirements.txt. Use `grep -v "opencv"` to exclude it.

### Error: `Could not find a version that satisfies the requirement X==Y.Z`
**Solution:** Use `>=` instead of `==` in requirements.txt.

### Error: `No such file or directory: '/home/conda/...'`
**Solution:** Clean up requirements.txt - remove all conda-specific paths (`@ file:///...`).

### Error: `ModuleNotFoundError: No module named 'flappy_bird_env'`
**Solution:** Copy the `flappy_bird_env` package directory into your project root.

### Error: `requirements.txt not found`
**Solution:** Submit job from the project directory: `cd /scratch/user/project && sbatch submit.sh`

### Error: `NameError: name 'sys' is not defined`
**Solution:** Add `import sys` to your Python script.
